Field note 03 / Prove

The Proof Loop

Build identity from evidence, not intensity.

7 minute readOpen accessLife Archive

People often try to change identity through declaration: “I am disciplined now,” “this time is different,” or “I finally understand.” A declaration can set direction, but it cannot carry the weight of proof.

The Proof Loop builds confidence differently. It creates a repeated cycle in which action produces evidence, evidence improves decisions and the archive makes progress visible across time.

Identity becomes durable when memory is no longer the only witness.

The loop

Use the same logic as the wider framework: observe the current state, choose one action with a clear completion condition, execute it under real conditions, measure the result, archive the evidence and adjust the next pass.

Define the evidence unit

A useful evidence unit is small enough to verify and meaningful enough to matter. “Worked on the project” is weak evidence because completion is undefined. “Published the framework page after checking all internal links” is inspectable.

  • Action: what will be done?
  • Condition: what constraints or safeguards apply?
  • Done: what observable result marks completion?
  • Evidence: where will the result be preserved?

Action: complete the daily status check.
Condition: maximum ten minutes; no redesigning the whole system.
Done: state, constraint and mission recorded.
Evidence: dated entry in Life Archive.

Measure leading indicators first

Large outcomes arrive late. Leading indicators measure actions that make the outcome more likely: meals completed, shutdown time kept, training sessions adapted to capacity, outreach sent, code shipped, reviews completed or high-risk situations avoided.

Record context without creating excuses

Evidence without context can mislead. Record a small state vector beside the action — sleep or subjective rest, energy, stress and system state where useful — so later review can distinguish capacity from execution.

Use misses as information

A missed commitment is not proof that the system is hopeless. Classify it: was the action too large, the completion condition vague, the environment poorly designed, or the priority simply wrong?

Run a weekly proof review

  1. What did I repeatedly complete?
  2. What failed more than once?
  3. Which condition predicted better execution?
  4. What should be removed, reduced or protected next week?
  5. What is the strongest evidence that autonomy increased?

Finish with one system change. Too many simultaneous improvements destroy the ability to learn which change mattered.

Build a trustworthy archive

Preserve both success and contradiction. Keep timestamps. Distinguish subjective scores from objective measurements. Record changes to definitions so that a metric does not quietly mean something different next month.

This protects against self-deception in both directions: inflated success stories and difficult days that erase evidence of real progress.

This field note is educational. Metrics and self-tracking should support wellbeing and decision quality, not compulsive monitoring, self-punishment or replacement of professional care.
